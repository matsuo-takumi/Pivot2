# ⚡ Performance Optimization

このドキュメントでは、Pivotプロジェクトにおけるパフォーマンス最適化のためのヒントとベストプラクティスを説明します。

## 1. General Performance Considerations

- **非同期プログラミング (`async/await`)**: UIスレッドをブロックする可能性のあるI/O処理（ファイルアクセス、ネットワーク通信、データベース操作など）や計算量の多い処理は、必ず `async/await` を使用して非同期で実行します。これにより、UIの応答性を維持し、ユーザーエクスペリエンスを向上させます。
- **マルチスレッド処理**: 大量のデータ処理やAI推論など、並列化可能なタスクは `Task.Run` や `Parallel.ForEach` などを利用して、複数のCPUコアを効率的に使用します。
- **リソースの適切な管理**: `IDisposable` を実装するオブジェクト（例: `HttpClient`, データベース接続、ファイルストリームなど）は、`using` ステートメントを使用して確実に解放します。これにより、メモリリークやリソース枯渇を防ぎます。
- **レイジーローディング**: 必要になるまでオブジェクトやデータをロードしない「レイジーローディング」戦略を採用します。例えば、画面に表示されていないアセットのサムネイルは、スクロールして表示範囲に入ってからロードします。

## 2. UI Performance Optimization

- **UI仮想化**: 大量のアイテムを表示するリスト (例: `ListView`, `GridView`) では、UI仮想化 (VirtualizingStackPanelなど) を利用して、画面に表示されるアイテムのみがUI要素として生成・レンダリングされるようにします。これにより、メモリ使用量とレンダリング負荷を大幅に削減します。
- **データバインディングの最適化**: `x:Bind` を使用して、コンパイル時の型安全性と高いパフォーマンスを確保します。不要なバインディングや複雑なConverterの使用は避けます。
- **UI要素の軽量化**: 可能な限り軽量なUIコントロールを使用し、カスタムコントロールを設計する際には、不要なオーバーヘッドを避けるようにします。
- **アニメーションの最適化**: アニメーションはUIスレッドをブロックしないように、可能な限りコンポジションレイヤーで実行されるもの (`CompositeTransform` など) を利用します。複雑なアニメーションは慎重に実装します。

## 3. Data and Database Optimization

- **データベースクエリの最適化**: 
  - 必要なデータのみを取得する (`SELECT *` を避ける)。
  - 適切なインデックスをテーブルに定義し、クエリのパフォーマンスを向上させる。
  - `JOIN` や `GROUP BY` を多用する複雑なクエリは、パフォーマンスボトルネックになる可能性があるため、慎重に設計・最適化する。
- **データキャッシュ**: 頻繁にアクセスされるが変更頻度の低いデータは、メモリキャッシュやファイルキャッシュを利用して、データベースへのアクセス回数を減らします。
  - `MetadataService` のハイブリッドDB構成では、ファイルシステムの変更検知とハッシュ比較によるキャッシュ更新を効率的に行います。
- **一括操作**: データベースへの挿入、更新、削除は、可能な限りバッチ処理（一括操作）で行い、個別のトランザクションオーバーヘッドを削減します。

## 4. AI Inference Optimization (AIClassifierService)

- **ONNX Runtimeの最適化**: 
  - **ハードウェアアクセラレーション**: GPU (CUDA, DirectMLなど) を利用できる環境では、ONNX Runtimeのプロバイダー設定でハードウェアアクセラレーションを有効にします。これにより、CPUよりも大幅に高速な推論が可能です。
  - **バッチ処理**: 複数の画像やデータに対してAI推論を実行する場合、可能な限りバッチサイズを大きくして一度に処理します。これにより、推論エンジンのオーバーヘッドを削減し、スループットを向上させます。
- **推論結果のキャッシュ**: 一度推論した結果は、MD5ハッシュなどのキーを使ってキャッシュし、同じ入力に対する再推論を避けます。これにより、不要な計算を削減し、ユーザー体験を向上させます。
- **モデルの軽量化**: 可能であれば、より軽量なAIモデル（量子化モデルなど）を使用することを検討します。これにより、推論速度を向上させ、メモリ使用量を削減できます。

## 5. File System Optimization (FileScannerService)

- **非同期I/O**: ファイルの読み書き操作は、非同期API (`FileStream.ReadAsync`, `File.WriteAllBytesAsync` など) を使用して、I/O処理中にUIスレッドがブロックされないようにします。
- **並列ファイルスキャン**: `FileScannerService` はマルチスレッドでファイルスキャンを実行し、I/Oバウンドな操作を並列化することで全体の処理時間を短縮します。
- **差分スキャン**: `FileSystemWatcher` とハッシュ比較を組み合わせることで、変更されたファイルのみを効率的にスキャンし、不要なフルスキャンを避けます。

## 6. Code Optimization

- **アルゴリズムの選択**: 計算量の多い処理では、より効率的なアルゴリズムを選択します。
- **メモリ割り当ての削減**: オブジェクトの生成頻度を減らし、可能な限り既存のオブジェクトを再利用します。特にループ内での不要なオブジェクト生成は避けます。
- **文字列操作**: `StringBuilder` を使用して、多数の文字列連結操作のパフォーマンスを向上させます。
- **コレクションの適切な選択**: `List<T>`, `Dictionary<TKey, TValue>`, `HashSet<T>` など、ユースケースに最適なコレクション型を選択します。
