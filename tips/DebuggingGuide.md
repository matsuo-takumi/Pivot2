# 🐛 Debugging Guide

このドキュメントでは、Pivotプロジェクトの開発における一般的なデバッグ手法とトラブルシューティングのヒントを説明します。

## 1. General Debugging Techniques (Visual Studio)

- **ブレークポイントの活用**: コードの特定の行にブレークポイントを設定し、実行を一時停止させます。変数の値、スタックトレース、アプリケーションの状態を確認できます。
- **ステップ実行**: F10 (ステップオーバー), F11 (ステップイン), Shift+F11 (ステップアウト) を使用して、コードの実行を細かく制御します。
- **ウォッチウィンドウとイミディエイトウィンドウ**: 実行中に変数の値を監視したり、式を評価したりするために使用します。
- **出力ウィンドウ**: `Console.WriteLine()` や `Debug.WriteLine()` で出力されたメッセージ、Serilogによるログ、例外情報などが表示されます。
- **例外設定**: 「デバッグ」->「ウィンドウ」->「例外設定」で、特定の例外がスローされたときにデバッガーが停止するように設定できます。

## 2. Logging and Error Handling

- **Serilogの活用**: PivotプロジェクトではSerilogをロギングフレームワークとして使用しています。問題発生時には、`logs/` ディレクトリに生成されるログファイル (`.log`) を詳細に確認してください。
  - **ログレベル**: `Debug`, `Information`, `Warning`, `Error`, `Fatal` などのログレベルを適切に利用し、必要な情報が記録されていることを確認します。
  - **構造化ロギング**: Serilogの構造化ロギング機能により、ログメッセージだけでなく、関連するオブジェクトのプロパティも記録されます。これにより、問題発生時のコンテキストを詳細に把握できます。
- **例外処理**: 重要な操作には `try-catch` ブロックを適切に配置し、予期せぬエラーが発生した際にアプリケーションがクラッシュしないようにします。例外はログに記録し、必要に応じてユーザーに通知します。

## 3. UI/UX Debugging

- **XAMLホットリロード**: Visual StudioのXAMLホットリロード機能を使用すると、アプリケーションを実行しながらXAMLの変更をリアルタイムで確認できます。
- **ライブビジュアルツリー**: 「デバッグ」->「ウィンドウ」->「ライブビジュアルツリー」を使用すると、実行中のアプリケーションのUI要素の階層構造を確認できます。これにより、意図しないレイアウトやバインディングの問題を特定できます。
- **データバインディングのデバッグ**: XAMLのバインディングエラーは、通常、Visual Studioの出力ウィンドウに表示されます。バインディングパス、プロパティ名、Converterの適用などを確認します。

## 4. Specific Module Debugging Tips

- **FileScannerService**: 
  - スキャン対象のルートフォルダが正しく設定されているか (`settings.json`) 確認します。
  - `FileSystemWatcher` が正しくファイル変更イベントを購読しているか、ログを確認します。
  - 大量のファイルをスキャンする場合、パフォーマンスボトルネックがないかプロファイリングツールで確認します。
- **MetadataService**: 
  - SQLite/LiteDBのデータベースファイルが正しく作成・更新されているか確認します。
  - データベースへのCRUD操作がトランザクション内で正しく処理されているか確認します。
- **AIClassifierService**: 
  - ONNXモデルが正しくロードされているか、モデルパスが正しいか確認します。
  - AI推論の結果 (`AITags`, `Confidence`) が期待通りであるか、または推論時間が許容範囲内であるか確認します。
  - 推論結果のキャッシュが正しく機能しているか確認します。
- **PluginManager**: 
  - 外部DLLが正しいディレクトリに配置され、署名検証が成功しているか確認します。
  - プラグインが実装している `IPlugin` インターフェースのメソッドが正しく呼び出されているか確認します。

## 5. Performance Debugging

- Visual Studioの「診断ツール」ウィンドウを使用し、CPU使用率、メモリ使用量、UI応答性などを監視します。
- `PerformanceOptimization.md` を参照し、一般的なパフォーマンス最適化のヒントを確認します。

## 6. Common Issues and Solutions

- **ファイルアクセス拒否**: アプリケーションが特定のファイルやディレクトリにアクセスできない場合、管理者権限で実行するか、アクセス権を確認してください。
- **データベースロック**: データベースが他のプロセスによってロックされている場合、アプリケーションを再起動するか、データベース接続を正しく閉じるコードを確認してください。
- **UIフリーズ**: 長時間実行される処理がUIスレッドをブロックしている可能性があります。`async/await` を使用して非同期処理に切り替えるか、バックグラウンドスレッドで処理を実行してください。
